Baixei o projeto.
Onde eu coloco os arquivos?

Você vai colocar os arquivos em uma pasta privada de código no GitHub e conectar essa pasta a uma hospedagem, como o Render. A hospedagem transforma o projeto em um endereço que a equipe abre no celular.

Não precisa colar os códigos no Google Sheets ou no Apps Script. O Sheets será a planilha de consulta e importação. Abrir apenas o arquivo index.html no computador mostra a interface, mas não ativa login ou gravação.

1 · NO SEU COMPUTADOR

Baixe e extraia o ZIP novo

  1. Baixe o projeto atualizado pelo botão “Baixar projeto” do Site.
  2. Clique em “Extrair tudo” ou descompacte o arquivo. Você terá uma pasta chamada ensina-presencas.
  3. Abra essa pasta. Você deve ver package.json, Dockerfile e as pastas server, db, dist, examples, tests e docs.
  4. Se ainda não instalou a versão anterior, use somente o novo ZIP. Não precisa juntar as duas versões.

A pasta certa é aquela onde está package.json. Essa será a raiz do projeto nos próximos passos.

2 · NO GITHUB

Coloque os arquivos em um repositório privado

  1. Entre em github.com com a conta da organização ou com uma conta autorizada.
  2. Crie um repositório novo chamado ensina-presencas e marque Private.
  3. Use “uploading an existing file” ou Add file → Upload files.
  4. Envie o conteúdo da pasta extraída, preservando suas subpastas. Não envie só o ZIP e não crie uma pasta extra envolvendo todo o projeto.
  5. Confirme o envio com “Commit changes”. Na página principal do repositório, Dockerfile e package.json devem aparecer diretamente.

Inclua package-lock.json, .gitignore, .dockerignore e .env.example. Se seu computador esconder arquivos iniciados por ponto, habilite a visualização deles para esse envio.

Nunca envie .env, senhas, chaves JSON ou backups. A pasta node_modules não é necessária. O repositório recebe o código; os segredos entram somente no painel da hospedagem.
3 · NO RENDER

Use Supabase Free para o banco e Render Free para o site

  1. Abra dashboard.render.com. Conecte a conta GitHub e autorize o acesso apenas ao repositório necessário.
  2. Antes de criar o site, abra Supabase, crie uma organização Free e um projeto gratuito. Em Connect → Session pooler, copie a conexão da porta 5432. Guarde-a como segredo DATABASE_URL. Desative a Data API; o banco será usado somente pelo servidor.
  3. Crie um Web Service, escolha o repositório enviado e selecione ambiente Docker. O Dockerfile já está pronto na raiz. Em Instance Type, selecione Free (US$ 0). Não crie Render Postgres, Background Worker ou Cron Job.
  4. Configure as variáveis indicadas na tabela abaixo. Se o provedor permitir, reserve primeiro o serviço para conhecer sua URL e configure tudo antes da publicação inicial. Se houver tentativa de inicialização sem variáveis, o servidor para sem permitir operação.
  5. Em Advanced → Docker Command, use o comando abaixo.
sh -c 'node server/migrate.js && node server/bootstrap.js && node server/seed-event.js && node server/index.js'

Esse comando prepara o banco, cria seu primeiro administrador, cadastra os 12 períodos desativados e inicia o site. Ele não apaga registros nem substitui horários já ajustados.

4 · NO GOOGLE CLOUD

Autorize o login com Google

  1. Abra console.cloud.google.com e use um projeto institucional.
  2. Configure a aplicação no Google Auth Platform. Prefira público Interno se seu Workspace permitir.
  3. Crie um cliente OAuth do tipo Aplicativo da Web.
  4. Cadastre como URI de retorno a URL operacional seguida de /auth/callback. Exemplo ilustrativo: https://seu-site.onrender.com/auth/callback.
  5. Copie ID e segredo para as duas variáveis Google do serviço web. O APP_ORIGIN deve corresponder à mesma origem.

Não cadastre a URL da demonstração ChatGPT como retorno da aplicação operacional. O guia técnico explica consentimento, usuários de teste, desenvolvimento local e acesso negado.

5 · NO GOOGLE SHEETS

Conecte a planilha

  1. No Google Cloud, habilite a Google Sheets API e crie uma conta de serviço dedicada. Se sua organização permitir, gere a chave JSON e coloque-a na variável secreta da hospedagem. Se a criação de chaves for bloqueada, acione o suporte institucional.
  2. Crie uma planilha com as abas Participantes, Periodos e Presencas.
  3. Compartilhe a planilha como Editor com o e-mail client_email dessa conta de serviço. Os operadores não precisam receber acesso à planilha.
  4. Use os arquivos da pasta examples como modelos: participantes.csv, periodos.csv e presencas.csv. Preserve os cabeçalhos.
  5. Formate as colunas como texto simples. Use datas ISO e os valores true/false em minúsculas.
  6. Copie o ID da URL da planilha para SHEETS_ID.
Presencas é uma aba de saída. As entradas são salvas primeiro no banco. As abas de cadastros são importadas por um administrador, quando solicitado; não há sincronização automática de ida e volta.
6 · SEM SERVIÇO EXTRA

A sincronização já roda dentro do site

Defina SHEETS_SYNC_MODE=inline e SYNC_INTERVAL_MS=60000 nas variáveis do serviço web. Não crie Background Worker ou Cron Job. Eles não são necessários nesta versão.

Enquanto o site estiver ativo, ele envia as presenças pendentes à planilha a cada minuto. Ao hibernar, a sincronização pausa e retoma quando o site reabrir. O botão do ADMIN permite sincronizar antes de fechar a operação.

No Render Free, o site pode hibernar após 15 minutos sem acesso e levar cerca de um minuto para reabrir. O Supabase Free pode pausar após uma semana de baixa atividade. Confira ambos antes do piloto e do evento. Isso evita depender de um plano pago, mas não oferece garantia de disponibilidade.
7 · NO SITE OPERACIONAL

Revise os horários e faça o piloto

  1. Abra a URL do Render e entre com o e-mail institucional configurado como primeiro ADMIN.
  2. Em Administração → Períodos, confira as 12 linhas, de 11 a 16/01/2027. Ajuste os horários reais e ative os períodos necessários.
  3. Os horários fornecidos são exemplos: manhã 08h–12h e tarde 13h–18h. Eles não foram confirmados por você.
  4. Cadastre os operadores e importe a lista de participantes. Emita e imprima os QR Codes.
  5. Faça o piloto com 6–8 celulares antes de liberar o uso real. O roteiro completo está em docs/PILOTO.md.

Antes de janeiro, o ambiente de produção ficará sem período aberto. Para ensaiar antes do evento, use uma instalação separada de homologação, com outras datas de teste configuradas no servidor. Não altere a data dos celulares.
